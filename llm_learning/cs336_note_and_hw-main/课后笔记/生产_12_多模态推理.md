## 一、多模态模型的基本架构

### 1.1 典型架构

```
                    ┌──────────────────┐
  图像/视频 ────────►│  Vision Encoder  │──┐
                    │  (ViT/CLIP/SigLIP)│  │
                    └──────────────────┘  │
                                          ▼
                    ┌──────────────────┐  ┌──────────────────┐
  音频 ────────────►│  Audio Encoder   │─►│  Connector/       │
                    │  (Whisper etc.)  │  │  Projector        │
                    └──────────────────┘  │                   │
                                          │  将异构模态的      │
  文本 ────────────► Tokenizer ────────►│  嵌入映射到统一    │──► Language Model (LLM)
                                          │  的 LLM 隐空间    │    (Decoder Layers)
                                          └──────────────────┘

  关键流程：
  1. Vision Encoder (ViT) 输出 patch embeddings
  2. Audio Encoder 输出 audio frame embeddings  
  3. Projector/Connector 将各 modal 的嵌入投影到 LLM 的 hidden_size
  4. 文本 token embeddings 与投影后的多模态嵌入在 prompt 中交错拼接
  5. LLM 对合并后的 hidden states 进行自回归解码
```

### 1.2 与纯文本推理的核心差异

| 维度 | 纯文本 LLM | 多模态 LLM |
|------|-----------|-----------|
| **输入** | 仅 token ids | token ids + 图像/音频/视频 |
| **Pre-LM 阶段** | Embedding lookup | Vision/Audio Encoder 前向 → Embedding lookup |
| **Prompt 结构** | 纯 token 序列 | 文本 token + 图像/音频占位符 token |
| **显存开销** | 仅 LLM 权重 + KV Cache | 额外：Encoder 权重 + Encoder 激活 |
| **调度复杂度** | token-level batching | 需要考虑 encoder 计算预算 |
| **Prefill** | 单步 | 可能两步：encoder 前向 + decoder prefill |

## 二、多模态配置：MultiModalConfig

[`vllm/config/multimodal.py#L73-L199`](file:///e:/cs336_note_and_hw-main/cs336_note_and_hw-main/HLIEvLLM-1.4.0rc0/vllm/config/multimodal.py#L73-L199)

```python
class MultiModalConfig:
    limit_per_prompt: dict           # 每种 modal 每 prompt 最大数量 (默认 999)
    mm_encoder_tp_mode: str = "weights"  # "weights" / "data"
      # "weights": TP 按层切分权重 (默认)
      # "data":   每个 TP rank 持有完整权重，输入 batch 分片 (batch-level DP)
    mm_encoder_attn_backend: AttentionBackendEnum | None
      # ViT 编码器的 attention backend (如 FLASH_ATTN)
    mm_encoder_attn_dtype: Literal["fp8"] | None
      # FP8 量化 ViT 编码器 attention
    mm_processor_cache_gb: float = 4
      # 处理器缓存大小 (GiB)，避免重复处理相同图像/音频
    mm_processor_cache_type: str = "lru"  # "lru" / "shm"
    enable_mm_embeds: bool = False
      # 允许直接传入预计算 embedding (跳过 encoder)
    mm_encoder_only: bool = False
      # 仅运行编码器 (disaggregated 模式)
    interleave_mm_strings: bool = False
      # 完全交错的多模态 prompt 支持
    video_pruning_rate: float | None
      # 视频 token 剪枝率 (Efficient Video Sampling)
    mm_tensor_ipc: str = "direct_rpc"  # "direct_rpc" / "torch_shm"
      # 跨进程多模态张量传输方式
```

## 三、核心数据结构

### 3.1 PlaceholderRange — 多模态 token 在 prompt 中的位置

[`vllm/multimodal/inputs.py#L118-L215`](file:///e:/cs336_note_and_hw-main/cs336_note_and_hw-main/HLIEvLLM-1.4.0rc0/vllm/multimodal/inputs.py#L118-L215)

```python
@dataclass(frozen=True)
class PlaceholderRange:
    offset: int               # prompt 中占位符的起始位置

    def get_num_embeds(self) -> int:
        """实际需要的嵌入向量数"""
        if self.embeds_cumsum is None:

        return self.embeds_cumsum[-1]

    def get_embeds_indices_in_range(self, start_idx, end_idx):
        """
        Chunked prefill 中精确定位嵌入区域。
        例如：PlaceholderRange(offset=2, length=5, is_embed=[F,T,F,T,T])
        start_idx=3, end_idx=5 → (1, 3)
        """
        ...
```

**设计意图**：不是所有占位符 token 都需要替换为 encoder 输出。例如 Qwen2-VL 的 `<|vision_start|>` 和 `<|vision_end|>` 标记 token 就是普通 embedding lookup，只有中间的 `<|image_pad|>` 需要替换为 ViT 输出。

**Chunked Prefill 适配**：当 prefill 被分块时（如 8192 token 分两批），`get_embeds_indices_in_range()` 精确计算当前 chunk 覆盖了哪些嵌入位置。

### 3.2 MultiModalKwargsItems — 处理后数据的嵌套结构

```
MultiModalKwargsItems (顶层, 按 modality 分组)
├── "image": [
│     MultiModalKwargsItem({"pixel_values": tensor_A, "image_grid_thw": ...}),  # 图1
│     MultiModalKwargsItem({"pixel_values": tensor_B, "image_grid_thw": ...}),  # 图2
│   ]
├── "audio": [
│     MultiModalKwargsItem({"input_features": tensor_C}),   # 音频1
│   ]
└── "video": [
│     MultiModalKwargsItem({"pixel_values_videos": tensor_D, "video_grid_thw": ...}), # 视频1
│   ]
```

**Field 合并策略**（`MultiModalFieldConfig`）：

| 策略 | 含义 | 示例 |
|------|------|------|
| `batched` | 沿 dim=0 stack | 3 张图 → `(3, C, H, W)` |
| `flat` | 沿指定维度 concat | 3 段不同长度音频 → `(total_frames, feature_dim)` |
| `shared` | 同一份数据复制 N 份 | 所有视频共享同一个 ViT |

## 四、完整数据流

### 4.1 宏观流程

```
┌─────────────────────────────────────────────────────────────────┐
│  P0 进程: API Server                                             │
├─────────────────────────────────────────────────────────────────┤
│  1. 用户请求 (image_url, audio_url, multi_modal_data)           │
│  2. MediaIO 下载/读取媒体数据                                    │
│  3. MultiModalDataParser 解析                                    │
│  4. MultiModalHasher 生成 hash (blake3)                          │
│  5. ProcessorCache: 检查是否已经处理过                           │
│     ├─ 命中 → 跳过 HF 处理                                      │
│     └─ 未命中 → 调用 HuggingFace Processor                       │
│         ├─ ImageProcessor 处理图像                               │
│         └─ → MultiModalKwargsItems                              │
│  6. 构造 MultiModalFeatureSpec → IPC 传给 P1                    │
└───────────────────────────┬─────────────────────────────────────┘
                            │ mm_tensor_ipc: "direct_rpc" 或 "torch_shm"
┌───────────────────────────▼─────────────────────────────────────┐
│  P1 进程: Engine Core                                            │
├─────────────────────────────────────────────────────────────────┤
│  7. Scheduler 调度                                               │
│     └─ scheduled_encoder_inputs: 决定哪些 encoder input 需本步   │
│  8. EncoderCache.add_request() → 注册 mm_features                │
│  9. GPUModelRunner.execute_model()                               │
│     └─ get_mm_embeddings() → 核心嵌入生成                        │
└─────────────────────────────────────────────────────────────────┘
```

### 4.2 核心路径：get_mm_embeddings()

```
get_mm_embeddings()
  │
  ├─ 1. EncoderRunner.prepare_mm_inputs()
  │     └─ 从 EncoderCache 取出本步需要的 mm_kwargs
  │
  ├─ 2. EncoderRunner.execute_mm_encoder()
  │     └─ model.embed_multimodal(**mm_kwargs_batch)
  │         ├─ 按 modality 分组
  │         ├─ "image": pixel_values → Vision Transformer → patch embeddings
  │         ├─ "audio": input_features → Audio Encoder → frame embeddings
  │         └─ → 返回 MultiModalEmbeddings (list[Tensor] | Tensor)
  │
  ├─ 3. 缓存 encoder 输出
  │     └─ encoder_cache.encoder_outputs.update(zip(mm_hashes, encoder_outputs))
  │
  ├─ 4. EncoderRunner.gather_mm_embeddings()
  │     └─ 按 PlaceholderRange 精确定位并收集嵌入
  │         ├─ get_embeds_indices_in_range(start, end) 处理 chunked prefill
  │         └─ 构建 mm_embeds tensor + is_mm_embed mask
  │
  └─ 5. EncoderRunner.get_inputs_embeds()
        └─ model.embed_input_ids(input_ids, mm_embeds, is_mm_embed)
            ├─ 对文本 token: 正常 embedding lookup
            └─ 对 MM token: scatter 替换为 encoder 输出
```

### 4.3 embed_input_ids — 文本嵌入 + 多模态嵌入融合

这是整个多模态推理中最重要的融合操作：

```python
def embed_input_ids(self, input_ids, multimodal_embeddings, is_multimodal):
    # Step 1: 所有 token 做 embedding lookup
    text_embeds = self.model.embed_tokens(input_ids)  # (n_tokens, hidden_size)

    # Step 2: 将多模态 token 位置的 embedding 替换为 encoder 输出
    if is_multimodal is not None and is_multimodal.any():
        text_embeds[is_multimodal] = multimodal_embeddings.to(
            device=text_embeds.device, dtype=text_embeds.dtype
        )

    return text_embeds
```

对于 chunked prefill（分块预填充），只有当前 chunk 中对应位置才 scatter：

```python
# chunked prefill 中的精确 scatter
for idx, (start, end) in enumerate(mm_positions):
    embeds_indices = placeholder_range.get_embeds_indices_in_range(
        start - token_start_idx_in_batch,
        end - token_start_idx_in_batch
    )
    token_slice = slice(start, end)
    text_embeds[token_slice][embeds_mask[token_slice]] = mm_embeddings[idx][...]
```

## 六、编码器缓存系统

### 6.1 两级缓存架构

```
                 P0 (API Server)                    P1 (Engine Core)
┌─────────────────────────────────┐    ┌─────────────────────────────────┐
│ MultiModalProcessorOnlyCache    │    │ EncoderCache                    │
│ • key: MM hash (blake3)         │    │ • mm_features: req_id→[specs]   │
│ • value: processed kwargs       │    │ • encoder_outputs: hash→Tensor   │
│ • 避免重复 HF 处理              │    │ • 避免重复 encoder 前向           │
│ • LRU / ShmObjectStore          │    │ • 模型权重更新时清理             │
└─────────────────────────────────┘    └─────────────────────────────────┘
```

**缓存命中流程**：
1. 图像 A 首次被请求 → HF 处理 + ViT 编码 → 缓存 key = hash(pixels)
2. 图像 A 再次被请求（同一图片、不同 prompt）→ 直接从缓存取 processed kwargs + encoder output
3. encoder_outputs 在 GPU 上，直接作为 embedding 插入 prompt

### 6.2 MultiModalHasher

对媒体数据生成唯一标识：

- **图像**：对 `pixel_values` tensor 做 blake3 hash（比 SHA256 快 ~10x）
- **音频**：对 `input_features` tensor 做 hash
- **视频**：对帧序列 tensor 做 hash
- 支持 `enable_mm_embeds` 模式下对预计算 embedding 做 hash

### 6.3 缓存管理

- **LRU 模式**：`mm_processor_cache_gb` 控制大小，容量满时淘汰最不常用项
- **SHM 模式**：使用共享内存 FIFO 缓存，`mm_shm_cache_max_object_size_mb` 限制单对象大小
- **跨进程同步**：P0 处理后的 kwargs 通过 `direct_rpc`（序列化）或 `torch_shm`（零拷贝共享内存）传给 P1

## 七、编码器预算管理

[`vllm/multimodal/encoder_budget.py`](file:///e:/cs336_note_and_hw-main/cs336_note_and_hw-main/HLIEvLLM-1.4.0rc0/vllm/multimodal/encoder_budget.py)

### 7.1 为什么需要预算

多模态推理的 encoder（ViT/Audio Encoder）是**计算密集型**的，和 LLM decoder 竞争 GPU 资源。需要在调度时限制每个 batch 的 encoder 负载。

### 7.2 预算计算公式

```python
# 1. 每张图/每段音频的最大 token 数
max_tokens_per_item = processor.get_mm_max_tokens_per_item()
# 例如：Qwen2-VL 用 ViT-bigG: 448×448 图像 → 1024 tokens

# 2. 每个请求最多允许的 MM 项数
mm_max_items_per_prompt = min(
    mm_limit_per_prompt,            # 用户配置的限制
    max_model_len // max_tokens_per_item  # decoder 容量限制
)

# 3. 每个 batch 最多允许的 MM 项数
mm_max_items_per_batch = min(
    encoder_compute_budget,         # encoder 计算预算
    max_num_reqs * mm_max_items_per_prompt  # 请求数限制
)
```

### 7.3 encoder_compute_budget 的来源

不是用户直接配置的，而是 vLLM 启动时通过 profiling 自动测量：

1. 用 dummy 输入跑一次 ViT forward
2. 测量 encoder 的显存占用量和计算时间
3. 根据可用的 GPU 显存和 `max_num_seqs` 反推合理的 encoder batch 限制

## 八、Encoder TP 模式

### 8.1 weights 模式 (默认)

```
TP Rank 0: Vision Layer 0[0:middle] → ... → Vision Layer N[0:middle]
TP Rank 1: Vision Layer 0[middle:end] → ... → Vision Layer N[middle:end]
```
- 和 LLM 的 Tensor Parallel 一样，按层切分权重
- 适用于 ViT 权重较大（如 ViT-g/14 有 ~1B 参数）的场景
- 每个 rank 处理全部输入，通信发生在层间

### 8.2 data 模式

```
TP Rank 0: 完整 ViT，处理 images[0:batch/2]
TP Rank 1: 完整 ViT，处理 images[batch/2:end]
```
- 每个 rank 持有完整 ViT 权重，输入 batch 分片处理
- 适用于 ViT 权重较小（~300M 参数）但 batch 中图片很多（~16 张）的场景
- 无层间通信，仅输出时需要 all_gather

### 8.3 如何选择

| 场景 | 推荐 |
|------|------|
| ViT 参数 > 1B，batch 图片少 | `weights` |
| ViT 参数 < 500M，batch 图片多 (如批量 OCR) | `data` |
| 模型不支持 data 模式 | 自动 fallback 到 `weights`（由 `supports_encoder_tp_data` 控制） |

## 九、视觉编码器集成示例

### 9.1 CLIP Vision Encoder

`vllm/model_executor/models/clip.py` 中实现适配 vLLM 的 CLIP：

```python
class CLIPVisionTransformer(nn.Module):
    """vLLM 适配版 CLIP Vision Transformer"""
    def forward(self, pixel_values):
        # patch embedding
        embeddings = self.embeddings(pixel_values)  # (B, num_patches, hidden)
        # pre-layernorm + transformer
        for layer in self.encoder.layers:
            embeddings = layer(embeddings)
        # post-layernorm
        return self.post_layernorm(embeddings)  # (B, num_patches, hidden)
```

**关键适配点**：
- 使用 vLLM 的 `AttentionBackendEnum` 选择 attention 后端（如 `FLASH_ATTN`）
- 支持 `mm_encoder_attn_dtype="fp8"` 的 FP8 量化 attention
- 通过 `MULTIMODAL_REGISTRY.register_processor` 注册到全局

### 9.2 VisionEncoderInfo — 编码器规格抽象

```python
class VisionEncoderInfo(ABC):
    """编码器元信息的抽象基类"""
    def get_num_image_tokens(self, image_size) -> int:
        ...
    def get_image_size(self) -> int:
        ...
    def get_patch_size(self) -> int:
        ...
```

- CLIP: `num_image_tokens = (image_size / patch_size)^2 + 1` (含 CLS token)
- InternViT: 支持动态分辨率，token 数随图像尺寸变化
- SigLIP: 和 CLIP 类似但无 CLS token

## 十、nano-vllm 对比

nano-vllm **完全不支持多模态**。这是必然的——作为一个 ~1200 行的教学项目：

| 维度 | nano-vllm | HLIEvLLM |
|------|-----------|----------|
| 模态支持 | 纯文本 | 文本 + 图像 + 音频 + 视频 |
| 编码器 | 无 | ViT (CLIP/SigLIP/InternViT) + Audio Encoder + Projector |
| 输入数据结构 | 仅 `input_ids` | `input_ids` + `PlaceholderRange` + `MultiModalKwargsItems` |
| Prompt 构建 | 纯 token 序列 | 文本-图像-文本交错，占位符 token 机制 |
| 缓存 | 无 | 两级缓存：处理器缓存 (P0) + encoder 输出缓存 (P1) |
| 调度约束 | token-level budget | 额外 encoder budget 约束 |
| 代码量 | 0 行 | ~8000+ 行 |

## 十一、总结

### 核心设计模式

| 设计 | 应用 | 意义 |
|------|------|------|
| **Encoder-Decoder 解耦** | Vision/Audio Encoder 独立于 LLM | 编码器输出可缓存复用 |
| **PlaceholderRange + scatter** | 嵌入融合机制 | 精准控制文本/多模态 token 的嵌入来源 |
| **两阶段处理** | P0 HF 处理 + P1 encoder 前向 + P1 decoder | 独立缓存层级，避免重复工作 |
| **MultiModalBudget** | 编码器计算预算约束 | 防止 encoder 占用过多 GPU 资源 |
| **SupportsMultiModal Protocol** | 模型接口标准化 | 任何模型实现该接口即可接入多模态流程 |
| **两级缓存 + 零拷贝 IPC** | Processor cache (P0) + Encoder cache (P1) | 相同图像/音频只编码一次 |

### 与你工作的关联

1. **Houmo NPU 多模态支持**：如果要支持，核心挑战是 Vision Encoder 的 NPU 适配——CLIP/ViT 的 attention 和 MLP 都需要 NPU kernel
2. **编码器输出缓存**：单张图片编码一次后可在多个请求间共享，对 RAG + 多图场景非常关键
3. **Encoder Budget**：对 NPU 这样的专用硬件，encoder 和 decoder 的计算资源竞争需要单独建模
