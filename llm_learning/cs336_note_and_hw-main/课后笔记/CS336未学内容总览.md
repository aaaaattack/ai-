## 二、可学内容（按推荐顺序排列）

### 2.1 Ch1 hw1/hw2：BPE Tokenizer 完整实现

**文件**：
- `chapter1/hw1/pair_all_bpe_tokenzier.py` — BPE 训练：语料 → 字符 → 字节 → 合并规则 → vocab
- `chapter1/hw2/tokenizer_encode.py` — BPE 编码：文本 → token ids

**细分内容**：
| 子项 | 内容 | 行数 |
|------|------|------|
| 基础 BPE 训练 | 统计字节对频率、找最高频对、合并产生新 token | ~150 |
| 完整 BPE 训练 | 处理 Unicode 多字节字符（UTF-8 编码 → 字节级 BPE） | ~250 |
| 编码 | merge 规则应用、未知字符回退 | ~80 |
| 解码 | token ids → 字节序列 → UTF-8 文本 | ~30 |

**为什么可学**：
- 之前学 vLLM 时涉及到 tokenizer（如 XGrammar 需要 `TokenizerInfo`、多模态 placeholder token 等），理解 BPE 底层有助于看懂 tokenizer 相关问题
- 日常工作偶尔需要处理 token 映射、vocab 对齐等场景

**优先级**：低。用到时候再看即可。

### 2.2 Ch2 hw2：分布式训练 DDP ⭐ 最推荐

**文件**：
| 子文件夹 | 文件 | 内容 |
|----------|------|------|
| hw2-1 | `hw2-1.py` | 手写梯度 all-reduce + 参数同步 |
| hw2-2 | `ddp_model.py` | 封装 `DistributedDataParallel` 类 + `DistributedSampler` |
| hw2-2 | `one_node_train.py` | 单机多卡训练入口 |
| hw2-3 | `ddp_overlap_bucketed.py` | 通信与计算重叠 + 梯度 bucketing |

**细分内容**：
| 子项 | 内容 | 与你工作的关联 |
|------|------|---------------|
| 手写 DDP | `all_reduce(grad)` + `broadcast(param)` 实现梯度同步 | 理解 TP 中 ColumnParallel/RowParallel 的通信模式差异 |
| Ring AllReduce | 分块 + scatter-reduce + all-gather，带宽不随 GPU 数增加 | 生产 TP/NCCL 课中学过 CustomAllReduce，这里看训练侧的用法 |
| DistributedSampler | 数据集分片，每张卡拿不重叠的数据 | 推理不用，但概念对理解 DP 有帮助 |
| 梯度 Bucketing | 小梯度合并成大 bucket 再 all-reduce，减少通信次数 | 和 NCCL 通信优化直接相关 |
| 通信-计算 Overlap | `all_reduce` 和 `backward` 在不同 CUDA Stream 并行 | 之前学过的双 CUDA Stream（LoRA 课中的 base∥lora）原理相通 |

**为什么推荐**：
- 你已学 TP/NCCL（推理侧通信），DDP 是训练侧通信，对比学习能加深对 NCCL/通信的理解
- Bucketing、通信-计算 overlap 这些模式在推理中也有对应（KV Cache 异步 offloading、CustomAllReduce）
- 代码量少（总共 ~300 行），一下午就能学完

**优先级**：高。

### 2.3 Ch3：Scaling Law

**文件**：
- `chapter3/hw/isoflop.py` — isoflop 曲线拟合
- `chapter3/data/isoflops_curves.json` — 实验数据

**细分内容**：
| 子项 | 内容 |
|------|------|
| IsoFLOP 曲线 | 固定算力预算下，最优模型参数量 vs 训练 token 数的关系 |
| 幂律拟合 | 用 numpy 拟合 `L(N, D) = A/N^α + B/D^β + E` |
| Chinchilla 定律 | "模型参数和训练数据应该等比缩放"的结论 |
| 实践意义 | 什么场景选大模型+少数据 vs 小模型+多数据 |

**为什么可学**：
- 客户选型时高频问题："这个任务用 7B 还是 70B？训练数据够不够？"
- 对 MoE 模型的理解有帮助（MoE 是在参数和算力之间做 trade-off）
- 纯概念学习，不需要写代码

**优先级**：中。不写笔记，读一遍论文摘要 + 跑一下代码即可。
