## 🔴 P0：必学（3 项）

### 1. 量化推理全链路

**为什么是 P0**：你直接对接量化团队。需要理解从算法到部署的全流程。

| 子项 | 核心内容 | 推荐资源 |
|---|---|---|
| 1.1 基础 | INT8/FP8/INT4 数值表示、对称/非对称量化、per-tensor/per-channel scale | 量化白皮书 |
| 1.2 GPTQ | 逐列量化 + Hessian 补偿矩阵、W4A16 精度保持 | GPTQ 论文 (Frantar 2023) |
| 1.3 AWQ | 按激活分布选择重要通道、W4A16、scale 搜索 | AWQ 论文 (Lin 2024) |
| 1.4 SmoothQuant | 数学等价变换 `(X·diag(s))·(diag(s⁻¹)·W)`、W8A8 | SmoothQuant 论文 (Xiao 2023) |
| 1.5 KV Cache 量化 | FP8 KV Cache、精度-显存 trade-off | vLLM FP8 KV Cache 文档 |
| 1.6 Houmo 落地 | Helion `_fp8` kernel 实现、PTQ 流程、calibration 数据 | Houmo `ptq.py` + `build.py` |

**已有资源**：
- 本项目：`推理性能优化系统学习路线.md` 第六章（量化部分）
- Houmo 代码：`hmodel/gptqmodel/`（GPTQ 量化工具）、`models/llm/qwen3/ptq.py`

### 2. Pipeline Parallel (PP)

**为什么是 P0**：Houmo 已经在用 (`qwen3_pipeline/prefill_pp_decode_tp.py`)。多芯片部署的核心技术。

| 子项 | 核心内容 | 推荐资源 |
|---|---|---|
| 2.1 PP 原理 | 按层切分模型、微批次流水线、bubble 利用率 | GPipe 论文 (Huang 2019) |
| 2.2 PP vs TP | 通信量对比、适用场景、组合使用 (3D Parallel) | Megatron-LM 论文 |
| 2.3 Houmo 实现 | `prefill_pp_decode_tp.py`：prefill/decode 分离到不同芯片 | 本 repo Houmo 代码 |

**已有资源**：
- Houmo 代码：`houmo-examples-xh2/apis/inferences/qwen3_pipeline/`
- `prefill_pp_decode_tp.py` + `prefill_pp_decode_pp.py`

**已有资源**：

## 🟡 P1：重点（3 项）

### 4. Speculative Decoding

**为什么是 P1**：推理加速的核心算法手段。客户问"怎么再快一点"时的关键答案。

| 子项 | 核心内容 | 推荐资源 |
|---|---|---|
| 4.1 原理 | Draft Model → Target Model 验证 → 接受/拒绝采样 | SpecInfer 论文 (Miao 2023) |
| 4.2 Medusa | 多预测头、并行猜测多个 future token | Medusa 论文 (Cai 2024) |
| 4.3 Eagle | 特征级别的推测、更高接受率 | Eagle 论文 |
| 4.4 vLLM 实现 | `spec_decode/` 模块、batch expansion | vLLM 源码 |

**与 Houmo 的关联**：`hmm_file_specs` 中有 `draft_prefill_model_name` 和 `draft_decode_model_name` — 已经在编译 speculative draft model。

### 5. KV Cache Offloading

**为什么是 P1**：显存管理的高级手段，直接影响支持的最大 context length。

| 子项 | 核心内容 | 推荐资源 |
|---|---|---|
| 5.1 GPU→CPU Offload | LRU 淘汰、异步传输、prefetch | vLLM offloading 设计文档 |
| 5.2 CPU→Disk Offload | 长会话历史保存、恢复 | FlexGen 论文 |
| 5.3 多级缓存 | GPU (HBM) → CPU (DRAM) → Disk (SSD) 延迟-容量 trade-off | vLLM `kv_connector` |

### 6. 多硬件后端架构 ✅

**为什么是 P1**：理解 vLLM 如何抽象不同硬件，对你理解自家 NPU 的 vLLM 接入方式至关重要。

| 子项 | 核心内容 | 推荐资源 |
|---|---|---|
| 6.1 Platform 系统 | `Platform` 基类、`PlatformEnum`、entry_points 注册 | vLLM `platforms/` + `plugins/` |
| 6.2 CUDA/ROCm/XPU 对比 | 各后端的 attention kernel、量化方案差异 | vLLM `csrc/` |
| 6.3 Houmo Helion | 作为 GPU 仿冒后端 vs 独立 NPU 平台 | `vllm/kernels/helion/` |

**已有资源**：
- 已学：HLIEvLLM 平台插件分析（附录）
- vLLM 源码：`vllm/platforms/__init__.py`、`vllm/plugins/__init__.py`

## 🟢 P2：了解（4 项）

### 7. LoRA 推理 ✅

**核心**：`Y = W@X + B·A@X`，A/B 是小矩阵。Hot-swap adapter 不重载模型。

**推荐资源**：LoRA 论文 (Hu 2021)、vLLM `lora/` 模块。

### 8. 多模态推理 ✅

**核心**：Vision/Audio Encoder + LLM 的组合推理。`Qwen3-VL` 的 prefill stage 需要先跑 vision encoder。

**推荐资源**：LLaVA 论文、Qwen2.5-VL 技术报告、vLLM `multimodal/`。

### 9. Structured Outputs ✅

**核心**：采样时约束 token 空间（通过 logits bias + FSM/grammar）。xgrammar 库实现。

**推荐资源**：vLLM `structured_output/`、guidance 项目文档。

### 10. HTTP Server / OpenAI API ✅

**核心**：`asyncio` + FastAPI + OpenAI 兼容协议。`vllm serve` 一行启动。

**推荐资源**：vLLM `entrypoints/`、OpenAI API 规范。
