# Physical RSI / VLA / NPU 增量整理（2026-09-24 至 2026-09-29）

> 上次集中整理截止：2026-09-23。本文仅记录其后的新增资料；媒体或公司披露均标注来源性质，不等同于第三方验证。

## 一、Physical RSI 与机器人 Agent

### 1. CognitiveReality：语义 Gaussian-TSDF + LLM Agent 远程操作
- **类型**：论文 / 系统
- **日期**：2026-09-25（arXiv）
- **链接**：[arXiv 2609.31418](https://arxiv.org/abs/2609.31418)
- **核心内容**：将 RGB-D 流构建为带语义索引的 Gaussian-TSDF 地图，并通过 typed tools 将语音、VR 控制器射线与机器人动作绑定。论文报告本地 Qwen3-VL-8B router 的 tool exact match 为 81.24%，在两台四足机器人上完成 26/30 次导航请求、20/20 次重新观测请求。
- **工程意义**：Physical RSI 的落地不只是策略模型，还需要地图、工具调用、执行验证和长时程状态管理。
- **对 NPU/方案的启示**：需同时优化 VLM 推理、小型路由模型、地图更新和低延迟 tool loop。

### 2. RegenHarness：证据门控的实体 Agent 自我改进
- **类型**：论文 / 框架
- **日期**：2026-09-23（过去窗口内补录）
- **链接**：[arXiv 2609.27612](https://arxiv.org/abs/2609.27612)
- **核心内容**：通过版本化记忆、资源租约、恢复预算、回归检查和发布授权修改任务模板、路由策略和恢复策略，但不允许未经批准的权重更新或降低完成门槛。
- **工程意义**：Physical RSI 的近期可落地形态更像可审计的配置/策略自改进。
- **对 NPU/方案的启示**：SDK 应提供 trace、策略版本、失败原因和安全回滚接口。

## 二、投机解码与推理系统

### 3. vLLM Programmable KV Cache RFC
- **类型**：开源 / RFC
- **日期**：近期更新
- **链接**：[vLLM #57103](https://github.com/vllm-project/vllm/issues/57103)
- **核心内容**：面向 Agent 长会话、tool pause、sub-agent fork/join、prefetch、migration 和多级存储，要求评估 cache hit、重算 token、TTFT、端到端任务延迟、迁移字节和公平性。
- **工程意义**：KV cache 从内部实现变成可由 Agent 生命周期控制的系统资源。
- **对 M50/XH2A 的启示**：需要 admission、prefetch、eviction、migration、pin/unpin 和 rollback API。

### 4. vLLM sampling-mask logprob 对齐 RFC
- **类型**：开源 / RFC
- **日期**：2026-09-28
- **链接**：[vLLM #58959](https://github.com/vllm-project/vllm/issues/58959)
- **核心内容**：提议返回与 sampling-mask token ID 对齐的 logprob，用于 RL 的 top-p score centering；RFC 明确 speculative methods 需等 emitted-token alignment 和 probability semantics 解决后再支持。
- **工程意义**：投机解码不只影响 token 接受，还影响采样分布、logprob 和 RL 数据一致性。
- **对 NPU 的启示**：验证器接口应保留 token position、accept/reject mask 和 logprob provenance。

### 5. NebulaSD / DPara / H-Spec（过去 7 天补录）
- [NebulaSD](https://arxiv.org/abs/2609.29364)：多对多 draft/target 资源池；四 GPU 实验中 request-round processing rate 相比共置执行提升 72.6%。
- [DPara](https://arxiv.org/abs/2609.27396)：并行 drafter 与 verification overlap；Qwen3-8B/14B 上报告 3.21×/3.52×平均加速。
- [H-Spec](https://arxiv.org/abs/2609.24197)：复用 target KV，减少独立 drafter-side KV；报告 accepted length 提升 5.0%–13.3%。

## 三、AI 芯片与端侧部署

### 6. Arm：边缘 AI 的计算与存储协同
- **类型**：厂商技术文章
- **日期**：2026-09-24
- **链接**：[Arm：从数据到 Token](https://www.arm.com/zh-cn/company/news/2026/09/data-to-token-edge-ai-compute-storage)
- **核心内容**：Arm 强调 Decode 阶段持续访问 KV Cache，使内存容量、带宽和数据搬运效率直接决定生成式 AI 性能；其 Cortex-A320 + Ethos-U85 平台面向超过 10 亿参数边缘模型。
- **工程意义**：边缘大模型的瓶颈从算力单点转为计算、存储和数据传输系统协同。
- **对 M50/XH2A 的启示**：应把 memory hierarchy、DMA、KV cache 和算子调度作为统一指标。

### 7. Qualcomm：端侧 MoE 与异构编排
- **类型**：厂商公告 / 产业
- **日期**：2026-09-22 至 24（窗口内补录）
- **链接**：[Qualcomm 中文公告](https://www.qualcomm.cn/news/releases/2026/09/releases-2026-09-22-2)
- **核心内容**：第六代 Snapdragon 8 Elite Extreme Gen 6 通过 CPU/GPU/NPU 协同运行阶跃 30B-MoE；公告称运行内存需求降低超 50%，预填充吞吐超过 330 Token/s、解码吞吐超过 28 Token/s。以上为厂商披露，需独立复现。
- **工程意义**：端侧方案开始把 MoE、内存、异构调度和存储加载作为一个整体优化。
- **对 M50/XH2A 的启示**：客户 benchmark 不能只测 NPU TOPS，应覆盖模型加载、prefill、decode、内存峰值和持续功耗。

### 8. Fraunhofer RISC-V Secure Element
- **类型**：芯片/IP 公告
- **日期**：2026-09-28
- **链接**：[Fraunhofer 官方公告](https://www.iis.fraunhofer.de/en/pr/2026/press-release-risc-v-secure-element-licensable.html)
- **核心内容**：基于 OpenTitan 的 RISC-V Secure Element 完成硅验证，可授权集成到 SoC、ASIC 和 chiplet。
- **工程意义**：安全启动、设备身份和模型授权将成为 AI 加速器的客户交付要求。
- **对 NPU/PCIe 的启示**：评估 secure boot、固件签名、DMA isolation、设备身份和加密模型加载。

## 五、对后续 M50/XH2A 评测的直接建议

1. 增加 `KV bytes/token`、cache hit、prefetch 命中、迁移字节和 rollback 次数。
2. 将 `acceptance length`、TTFT、TPOT、p95、tokens/J 按请求记录，而不是只给平均值。
3. 评估 MoE 的模型加载、专家切换和 host/NPU 协同，不只测 dense GEMM。
4. 为 Agent/Physical RSI 客户增加 trace、策略版本、安全回滚和 DMA/设备审计字段。
